## 0. 阶段 0 的本质

不是发 PR、不是做营销、不是引流。**是测市场**：

> 把已经存在的 echo / rune 体系，用人话讲给陌生人听。
> 看他们（前端开发者 / 重度笔记用户 / DSL 爱好者）是否愿意：
> - 读完整篇文章（≥3 分钟停留）
> - 点 star / fork / 转发
> - 在评论区说"我也想写一个" / "我想接入"
> - 提交一个 PR 或一个 echo 模板 demo

如果连"陌生人愿意读完"都做不到，说明叙事失败，**不是产品失败**——是包装问题，可以重写；如果"愿意读完且有少量互动"，但"愿意写"的人 < 5，那说明**学习成本太高**，再调叙事后重测；如果"愿意写"的人 ≥ 5，进阶段 1。

## 6. 关键风险 & 应对

| 风险 | 应对 |
| --- | --- |
| 中文长文没人看 | 标题改 3 次，每次跑 A/B；优先在 V2EX `/r/Programmer` 节点首发，那里有"原创项目"调性 |
| 英文长文被 HN 喷"又一个 Notion 替代品" | 标题里**绝不提**"笔记 app"，主打"DSL / annotation / programmable"——避免与 Notion 头部撞 |
| 修仙命名被喷（生生不息、破万法） | 在长文里**先自嘲**："是的，命名很中二，但我觉得一个创作工具的术语应该有性格" |
| 桌面绑定被喷（为啥不是 VSCode 插件） | 公开回应："是，这正是阶段 1 要做的事：抽 SDK 出来" |
| 30 天内拿不到 5 个反馈 | 宣告失败，按用户拍板的"路径 1 失败 = 最终失败"决策收尾；保留所有素材，路径 2/3 不再启动 |
| 反向：30 天内有 50+ 反馈但都没质量 | 仍然进阶段 1，但要重新定义"质量"门槛（如：愿意看 README 才算） |
