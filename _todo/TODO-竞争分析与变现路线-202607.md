# TODO — 竞争分析与变现路线

> 决策日期：2026-07-29
> 范围：站在外部投资人 / 竞品视角，客观评估 coolma / Memocast 当前的技术复杂度、特色功能竞争力，并给出 3 条可能的赚钱路径
> 结论先行：**项目有真实差异化（rune / echo DSL + 博客部署管道），但还在"个人作品"阶段；商业化路径最可能是 rune 生态化 + 博客 SaaS 化，不是"再做一个 Notion 替代品"**
> 本文档只做决策与路径规划，不写实现代码；下一阶段再单独立 TODO 跟进

## 0. 方法论：用什么标尺评估

四个维度同时打分，避免"这个功能我喜欢"的主观偏差：

1. **技术复杂度** — 不是越复杂越好，要看"复杂度是否构成壁垒"还是"复杂度是负担"
2. **差异化** — 同行（Obsidian / Notion / Typora / Logseq / Memos / 为知 / 语雀）是否也做
3. **用户付费意愿** — 是否能想清楚"谁愿意付多少钱、为什么"
4. **可执行性** — 当前团队规模（推断 1 人），1 人能跑通吗

## 1. 技术复杂度盘点（客观事实）

### 1.1 项目体量

| 维度 | 数值 | 来源 |
| --- | --- | --- |
| 主项目 `src/` 文件数 | 633 | `Get-ChildItem src -Recurse -File` |
| 主进程 `src-electron/` 文件数 | 46 | 同上 |
| 插件子项目 `_plugins/` 文件数 | 200 | `box-im-wujie` / `doubao-input` / `layui` 三个独立工程 |
| Jest 套件 | 11（约 557+ 用例） | `package.json` 的 `yarn verify:*` 系列 |
| 累计依赖 | 150+ npm 包 | `package.json` |
| 第三方编辑器/渲染引擎 | Muya + Monaco + markmap + jsxgraph + reveal.js + mermaid + vega + lottie + shiki + katex + echarts + flowchart + microapp（wujie） | 多栈共存 |

### 1.2 复杂度归类

| 维度 | 评分（满分 5） | 评估 |
| --- | --- | --- |
| **架构复杂度** | 4 | Electron 主进程 + 渲染进程 + 3 个独立 Vue 子应用，wujie 微前端 + vuex + sqlite IPC + electron-store 混用 |
| **核心编辑引擎** | 4 | 二次封装 Muya，加 Monaco 双编辑器 + Block 树扩展 + 自研 `@xxx{...}(...)` 注解体系 |
| **数据/同步层** | 5 | 本地 SQLite (`sql.js`) + WizNote 云端双向 "本地优先" 同步，删日志、空笔记补回、kbGuid 映射、跨账号隔离、2004 错误回退 |
| **试验特性（rune / echo）** | 5 | 自研 DSL：16 张内置 echo + 14 个 SFC rune 模板 + 工厂 + jQuery handler 字符串编译 + 完整 Jest 契约测试 |
| **桌面能力** | 3 | 离线 store + 自动更新 + 窗口状态 + 7z 极致压缩；缺乏协作 / 移动端 |
| **测试护城河** | 3 | 11 个 Jest 套件覆盖 rune / echo 关键契约；缺云函数、DB schema、Muya parser、序列化解码 4 大缺口 |
| **UI 库混用** | 3 | Element-UI × Quasar × Ant Design Vue 三栈混用，有规约但读起来负担明显 |

> **一句话**：这不是一个"小项目"。但复杂度集中在**有产品意义的部分**（编辑器扩展、同步层、可编程 DSL），不是堆代码。

### 1.3 复杂度为何"不是负担"

- 大多数复杂度服务于**核心差异化**（rune / echo / 同步），不是补丁式堆功能
- 编辑器切换 / 同步 / 插件加载 三条主线在 `superpowers` 规则体系下有清晰边界
- 关键链路有 Jest 锁定契约，重构风险可控

## 2. 差异化盘点：哪些功能"别人没做 / 做得浅"

### 2.1 强差异化（独家）

#### A. Echo 注释体系（最大卖点）

> Markdown 行内用 `@echo名{props}(文本)` 触发 DOM 增强。
> 16 张内置卡片覆盖富表达：高亮、复读、折叠高亮、忽略、todo、广告标注、参考资料、diff 标记、双生花（克隆行）、破万法（屏蔽他 echo）、天行健（切主题）、离析（松排版）、招灾（哥特渐变）、夺心魄（劫持他 echo）、替罪（兜底错）、强运（AI 校对）。

- **核心创新**：echo-chant 之间可以互相作用（破万法屏蔽、夺心魄劫持）
- 这是 Obsidian / Notion / Typora 都没有的"装饰互动 DSL"
- 配合 rune 形成**可编程富文本**：作者在 Markdown 里写一个 `@xxx{...}` 就引入一个交互式组件

**对标对照**：

| 工具 | 类似能力 | 差距 |
| --- | --- | --- |
| Obsidian | Dataview、Plugin 钩子 | 插件式，要装 + 学专有 API |
| Notion | 块类型 + 子页 / 数据库 | 块类型是封闭的，作者无法自定义块语义 |
| Typora | 自定义 HTML 标签 | 只能写死样式，没法劫持其他 echo |
| coolma | `@xxx{props}(text)` 行内 DSL | **作者可编排 echo 之间的互动** |

#### B. Rune 远程导入 / 微前端内嵌

- `runeRemoteImportDialog` 支持从 GitHub url 直接 `hel-micro` 拉一个 Vue SFC 到笔记里
- 任意前端工程师写一个 rune 模板 → 推到 GitHub → 用户一键导入
- **这是潜在的"插件市场"雏形**

#### C. 本地优先同步模型（不是双向 merge）

- `SyncService` 显式声明"不与传统 conflict 兼容"
- 备份 / 恢复 / 删日志队列 / 空笔记补回 / 跨账号隔离 / 2004 错误回退策略完整
- 对离线场景强（断网时仍可写，恢复后自动备份）

**对标对照**：

| 工具 | 同步模型 | 我们的差距 / 优势 |
| --- | --- | --- |
| Obsidian | 多端 vendor lock-in（官方 Sync 服务） | 我们免费 + 本地真存 |
| Notion | 实时双向 | 协作强，离线弱 |
| Typora | 无 | 完全没有 |
| 为知 | 双向 + 冲突解决 | 我们的本地优先更可预测 |

#### D. 博客部署管道（写作 → 发布一体化）

- `BlogDeployService` + VuePress 1.x
- 一键把本地笔记打包成静态博客（vuepress / vdoing / hope / reco 主题）
- 支持 SFTP 推送 + GitHub Actions
- 中间产物 `id-mappings.json` / `seq-manifest.json` 解决 permalink 冲突
- **是少有的"写作 → 发布"一体化桌面工具**

**对标对照**：

| 工具 | 类似能力 | 差距 |
| --- | --- | --- |
| Obsidian | Digital Garden / Quartz 插件 | 插件式，配置成本高 |
| Memos | 一键 memos 公开页 | 仅 memos 类型，不能用 Markdown 全功能 |
| Notion | Super.so 第三方 | 第三方、收费 |
| coolma | 原生内置 | **优势：免费 + 全功能 Markdown** |

#### E. 富交互元素嵌入

- markmap 思维导图
- jsxgraph 数学互动画板
- reveal.js / Marp PPT 模式
- 写作时插入一个 `@jsxgraph{...}` 就能在笔记里跑数学交互
- 这是**写作 + 学习工具的合流**，与 Notion 的"嵌入第三方"是不同理念

### 2.2 中差异化（做得不错但不是独家）

- 标签 treemap（替代传统列表）+ 日历筛选（v2026-06 已做）
- AI 长对话 + 思考过程动画 + 流式 + 一键应用回笔记 + `portkey-ai` 多供应商切换
- 皮肤系统（哪吒红 / 12 星座 / MBTI 已规划）

### 2.3 偏弱（个人作品痕迹）

- 同步后端绑定 WizNote，用户群小
- 文档 / 教程 / 社区完全缺失
- 没有移动端（架构不考虑触摸）
- 不支持协作（单兵作战产品）

## 3. 赚钱路径可行性分析

> 三个方向，按"投入产出比 + 团队规模匹配度"排序

### 路径 1：Rune / Echo 生态化（评分 4.5 / 5）

#### 1.1 形态
- 把内置 16 张 echo + 14 张 rune 模板开源 / 半开源
- 做 rune 模板商店（创作者上传 → 审核 → 上架）
- 抽 SDK 出来，让其他编辑器（VSCode、Typora）也能用 @xxx{...}(...) DSL
- 收订阅：用户在商店下载付费模板 → 平台抽成 30%

#### 1.2 利润模型

| 模式 | 单价 | 预期客单价 |
| --- | --- | --- |
| 免费模板 | ¥0 | 拉新 |
| 单模板付费 | ¥5–50 | 抽 30% |
| 创作者订阅（按月） | ¥29/月 | 平台抽 30% |
| Pro 版本（高级 rune） | ¥39/月 | 用户直接付费 |

**乐观情景**：1000 个付费用户 × ¥50 = ¥50 万/年（模板）/ 1000 × ¥39 × 12 = ¥46 万/年（订阅）

#### 1.3 1 人可执行性

| 阶段 | 工作量 | 关键动作 |
| --- | --- | --- |
| 开源 SDK | 1 个月 | 把 echoRuntime / echoBuiltins 拆成独立 npm 包，文档化 |
| 模板商店 MVP | 2 个月 | 一个网页 + 提交表单 + 简单审核流，不需要登录的免登录下载 |
| 引入第一批创作者 | 持续 | V2EX / 即刻 / Twitter Developer 社区发"用 echo 写一个卡片"挑战 |
| 抽成模式 | 后置 | 半年后再设计 |

#### 1.4 关键风险

- **缺乏开发者社区**：需要先有内容创作者（前端开发者）愿意贡献 rune 模板
- **DSL 学习成本**：echo 名词（生生不息 / 破万法 / 夺心魄）有特色但也是门槛
- **竞品空白期**：Obsidian 插件市场已经成熟，但 echo 这种"行内注解"是空白，先发优势窗口约 12–18 个月

#### 1.5 决策

✅ **推荐**。这是 1 人能做、回报最实在、且能反哺产品（让更多用户创造更多模板）。

### 路径 2：博客 SaaS 化（评分 3.5 / 5）

#### 2.1 形态
- 把 `BlogDeployDialog` 升级为"SaaS 模式"
- 托管静态博客 + 自定义域名 + CDN 加速
- 用户写完笔记 → 一键发布到 `xxx.coolma.app` 或自定义域名
- 收订阅费（¥29/月起）

#### 2.2 利润模型

| 用户档位 | 月费 | 容量 | CDN 流量 |
| --- | --- | --- | --- |
| 免费 | ¥0 | 1 GB 静态资源 | 10 GB/月 |
| 基础 | ¥29 | 5 GB | 100 GB/月 |
| Pro | ¥99 | 50 GB | 1 TB/月 |
| 团队 | ¥299 | 500 GB | 10 TB/月 |

**乐观情景**：500 个付费用户 × ¥29 = ¥17.4 万/年

#### 2.3 1 人可执行性

| 阶段 | 工作量 | 关键动作 |
| --- | --- | --- |
| 后端 (Node + 对象存储) | 2 个月 | 阿里云 OSS / 腾讯云 COS / 七牛 |
| 部署管道改造 | 1 个月 | 把 SFTP 路径改成对象存储上传 |
| 计费 / 订阅 | 1 个月 | Stripe / 微信支付 |
| CDN 配置 | 1 周 | 阿里云 / Cloudflare |

#### 2.4 关键风险

- **运维成本高**：静态网站托管利润微薄，CDN 流量是大头
- **反垃圾 / 合规**：国内备案是个坎
- **替代品多**：语雀、Notion、Vercel、Cloudflare Pages 都在抢这块
- **域名 / 品牌**：coolma 域名 + 品牌认知几乎 0

#### 2.5 决策

🟡 **次选**。有现成管道可复用，但运维成本与替代品风险都偏高。**先做路径 1 积累品牌，再尝试 SaaS**。

### 路径 3：AI 写作助手（评分 3 / 5）

#### 3.1 形态
- AI drawer 已经做得很完整 + 一键应用回笔记
- 升级为：AI 校对（已有强运 echo） + 续写 + 风格转换 + 多语言翻译
- 收订阅费（¥39/月）

#### 3.2 利润模型

- 直接订阅：¥39 / 月 / 用户
- 乐观情景：300 个付费用户 × ¥39 × 12 = ¥14 万/年

#### 3.3 1 人可执行性

- 1–2 个月把现有 AI 能力打包成付费层
- 关键难点：token 成本控制 + 海外 / 国产模型差价

#### 3.4 关键风险

- **竞品恐怖**：Notion AI、Whisper AI、豆包、ChatGPT 都在抢
- **差异化弱**：AI 本身没有壁垒，差异化必须靠"与 echo 联动"（强运 / nice / pe这些 echo 名词）
- **付费意愿低**：用户已经在 Notion / ChatGPT 付费过一次

#### 3.5 决策

🟡 **次选**。作为"产品副业"做可以，但不应作为唯一路径。**与路径 1 配合**（AI 校对 echo 作为付费 rune 模板售卖）效果更好。

## 6. 推荐路线（按优先级）

### 阶段 0：内容验证（0–1 个月）

> 在投入工程前先验证"是否有人想要"

- [ ] 写一篇中文长文："为什么 Markdown 应该可编程"——把 echo 体系讲清楚
- [ ] 写一篇英文长文（同主题）——发到 HackerNews / Twitter / Dev.to
- [ ] 在 V2EX / 即刻 / Reddit r/ProgrammingLanguages 发"echo 公开挑战"：征集 3 个 echo 模板 demo
- [ ] 观察反馈：是否有人愿意贡献 / 询问实现细节 / 询问如何安装
- [ ] **决策开关**：如果 30 天内 5 个以上"我也想写一个"的反馈 → 进入阶段 1；否则重新考虑

### 阶段 1：SDK 化 + 模板市场 MVP（1–4 个月）

> 假设阶段 0 验证通过

- [ ] 把 `echoRuntime` / `echoBuiltins` 拆成独立 npm 包 `@coolma/echo-runtime`
- [ ] 把 `runeTemplates` 拆成独立 npm 包 `@coolma/rune-sdk`
- [ ] 写完整开发者文档：API / 模板示例 / 部署指南
- [ ] 做模板商店 MVP：一个静态网站 + JSON 清单 + 下载链接，无需账号
- [ ] 引入 5–10 个种子创作者（朋友圈 + V2EX / Twitter 写得好的前端开发者）
- [ ] 完成最初 30 个第三方模板上架

### 阶段 2：商业化（4–8 个月）

- [ ] 商店引入付费模板（¥5–50）
- [ ] 创作者中心：上传 / 定价 / 收入查看
- [ ] 抽成模式：平台 30% + 创作者 70%
- [ ] 接入 Stripe / 微信支付
- [ ] 启动 Pro 订阅：¥29/月（含高级 rune 模板 + AI 校对额度）

### 阶段 3：扩展（8–12 个月）

- [ ] 与路径 2 结合：把博客部署作为付费 rune 模板（"一键发布到博客"模板）
- [ ] 与路径 3 结合：把 AI 校对作为付费 rune 模板（强运 echo 升级版）
- [ ] 启动企业版：团队协作 + 权限 + 私有部署
