# 多符文渲染引擎机制 — 设计方案

> 文档版本：2026-06-21
> 状态：规划中，待实施
> 目标：为 Memocast 引入 Muya / Tiptap / Editor.js / Milkdown 四种符文渲染模式，用于教学目的

---

## 一、背景与目标

### 1.1 现状

Memocast 当前使用 **Muya** 作为 WYSIWYG Markdown 编辑器，并已在其基础上构建了一套完整的**符文（Rune）系统**：

- **符文（Block Rune）**：块级 Vue SFC 嵌入，用户通过 QuickInsert 插入占位符 `<div data-rune-name data-rune-id data-rune-node-id>`，Muya 在 `renderRunes()` 阶段通过 `RunePreviewRenderer` Vue 构造器动态挂载为 live Vue 实例
- **回响（Echo）**：行内标注语法 `@name{attrs}(prompt)`，通过 `echo_anno` tokenizer 解析为 token，Muya 在 `renderEchoPlaceholderNodes()` 中渲染为可交互卡片
- **双引擎并行**：Muya（富文本）与 Monaco（纯 Markdown）通过 `enablePreviewEditor` 状态变量切换，`v-show` 同时存在于 DOM

这套系统已经非常成熟，但**只有一种渲染引擎**（Muya），缺乏教学上的多样性视角。

### 1.2 目标

引入 **Muya / Tiptap / Editor.js / Milkdown** 四种渲染引擎的符文渲染模式，提供：

1. **教学价值**：同一套"符文数据"（RuneCard 定义）在四种不同渲染架构下如何表现，让用户/开发者直观理解各编辑器设计哲学
2. **架构隔离**：符文定义层（数据 + SFC）与渲染引擎层完全解耦，未来可随时替换或扩展
3. **最小侵入**：不改现有代码结构，以新文件/新目录引入，不影响现有 `enablePreviewEditor` 双引擎模式

### 1.3 非目标

- 不替换现有 Muya 编辑器作为主编辑器
- 不引入四种并行可用的富文本编辑器（仅作为符文预览/教学视图）
- 不修改 Muya / Monaco 的核心渲染逻辑

## 二、架构设计

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                      RuneDefinitionLayer                     │
│  (RuneCard[], SFC templates — 完全独立，不依赖任何渲染器)     │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   RuneEngineRegistry                         │
│  registerEngine(name, engine) · getEngine(name) · list()   │
└─────────────────────────────────────────────────────────────┘
          │            │            │            │
          ▼            ▼            ▼            ▼
    ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
    │  Muya    │ │  Tiptap  │ │Editor.js │ │ Milkdown │
    │ Engine   │ │ Engine   │ │ Engine   │ │ Engine   │
    └──────────┘ └──────────┘ └──────────┘ └──────────┘
```

**关键原则**：符文数据（`RuneCard`）和 SFC 模板源码作为"语义层"不变，每个引擎负责将这些符文渲染为可交互界面。

### 2.3 核心类型定义

```typescript
// RuneDefinition — 符文定义（数据层，与引擎无关）
interface RuneDefinition {
  id: string;
  name: string;
  desc: string;
  power: 'minor' | 'moderate' | 'major' | 'ultimate';
  color: string;
  icon: string;
  template: string;          // Vue SFC 源码字符串
  category?: string;
  tags?: string[];
}

// RuneValue — 符文在文档中的实例值
interface RuneValue {
  runeId: string;
  nodeId: string;
  value: any;               // 符文运行时数据
  payload?: Record<string, any>;
}

// RuneEngine — 引擎接口（所有引擎必须实现）
interface RuneEngine {
  /** 引擎唯一名称 */
  name: string;
  /** 引擎描述（教学用） */
  description: string;
  /** 引擎技术栈 */
  techStack: string;

  /**
   * 初始化引擎
   * @param container 挂载 DOM 容器
   * @param options   引擎选项
   */
  mount(container: HTMLElement, options: RuneEngineOptions): void;

  /**
   * 销毁引擎
   */
  destroy(): void;

  /**
   * 加载符文卡片列表
   * @param cards 符文定义数组
   */
  loadRuneCards(cards: RuneDefinition[]): void;

  /**
   * 在编辑器中插入符文
   * @param rune   符文定义
   * @param value  符文初始值
   * @returns 符文实例 ID
   */
  insertRune(rune: RuneDefinition, value?: any): RuneValue;

  /**
   * 更新符文值（符文内部数据变更时调用）
   * @param runeValue 符文实例
   * @param newValue  新值
   */
  updateRuneValue(runeValue: RuneValue, newValue: any): void;

  /**
   * 删除符文
   * @param runeValue 符文实例
   */
  removeRune(runeValue: RuneValue): void;

  /**
   * 获取编辑器当前内容（Markdown/JSON/HTML）
   */
  getContent(): string | object;

  /**
   * 从内容恢复符文
   * @param content 内容字符串
   */
  setContent(content: string | object): void;

  /**
   * 监听符文变更事件
   * @param callback
   */
  onRuneChange(callback: (event: RuneChangeEvent) => void): void;
}

interface RuneEngineOptions {
  /** 是否只读模式（教学展示用） */
  readOnly?: boolean;
  /** 主题 */
  theme?: 'light' | 'dark';
  /** 编辑器高度 */
  height?: number | string;
  /** 占位符文本 */
  placeholder?: string;
}

interface RuneChangeEvent {
  type: 'insert' | 'update' | 'remove';
  runeValue: RuneValue;
  fullContent: string | object;
}
```

## 三、四种引擎详细设计

### 3.1 Muya 符文引擎（`muya-engine`）

**技术基础**：现有 Memocast Muya 编辑器（snabbdom 虚拟 DOM，Vue 2 组件挂载）

**架构特点**：
- Block 树 → snabbdom vnode → 真实 DOM → `renderRunes()` 升级为 live Vue 实例
- `RunePreviewRenderer` Vue 构造器通过 `compileTemplateToFunctions()` 动态编译 SFC
- VM 生命周期由 `runeVmMap` 管理，DOM 节点移除时同步清理

**集成方式**：

```javascript
// src/components/ui/editor/rune-engines/muya-engine/index.js
import Muya from '@/libs/muya/lib';
import { normalizeRuneSfc, createRuneRendererCtor } from '../Muya.vue'; // 复用现有逻辑

class MuyaRuneEngine implements RuneEngine {
  name = 'muya';
  description = 'snabbdom 虚拟 DOM + Vue 2 动态编译渲染';
  techStack = 'snabbdom + Vue 2 + Block Tree';

  muya = null;
  runeCards = [];
  runeVmMap = new Map();

  mount(container, options) {
    this.muya = new Muya(container, {
      markdown: '# 符文编辑器\n\n请从左侧选择符文...\n',
      enableRuneVueRenderer: true,
      runeCards: [],
      // ... 复用现有选项
    });
    this.muya.on('change', ({ markdown }) => {
      this.emitChange({ type: 'update', runeValue: null, fullContent: markdown });
    });
  }

  loadRuneCards(cards) {
    this.runeCards = cards;
    // 为每个符文生成 Vue 构造器
    const runeRenderers = cards.reduce((acc, rune) => {
      const ctor = createRuneRendererCtor(rune);
      if (ctor) acc[rune.id] = ctor;
      return acc;
    }, {});
    this.muya.setOptions({ runeCards: cards, runeRendererCtors: runeRenderers });
  }

  insertRune(rune, value) {
    const nodeId = `rune-${Date.now()}`;
    const runeValue = { runeId: rune.id, nodeId, value };
    // 通过 Muya 的 command API 插入符文占位符
    this.muya.insertRuneTemplate(rune, value, nodeId);
    return runeValue;
  }

  // ... 其他方法
}
```

**教学要点**：
- snabbdom 的 diff/patch 机制
- Block 树作为中间表示（IR）层
- `tokenizer()` → `renderInlines[]` 的 token → vnode 分发模式
- 渲染后阶段的 DOM 升级（Vue 实例挂载）

### 3.2 Tiptap 符文引擎（`tiptap-engine`）

**技术基础**：Tiptap 2.x（ProseMirror），Vue 3 Node View

**架构特点**：
- 基于 ProseMirror，Schema 驱动，节点属性定义在 `addAttributes`
- 自定义节点通过 `addNodeView()` 注册 `NodeViewConstructor`
- Vue 3 组件通过 `VueNodeViewRenderer` 包装，渲染到 Portal

**集成方式**：

```javascript
// src/components/ui/editor/rune-engines/tiptap-engine/TiptapRuneExtension.js
import { Node, mergeAttributes } from '@tiptap/core';
import { VueNodeViewRenderer } from '@tiptap/vue-2-renderer';  // Tiptap 官方 Vue 2 支持
import TiptapRuneView from './TiptapRuneView.vue';

export const RuneNode = Node.create({
  name: 'rune',
  group: 'block',
  atom: true,  // 原子节点，不可继续拆分

  addAttributes() {
    return {
      runeId: { default: null },
      runeName: { default: '' },
      runeNodeId: { default: '' },
      runeValue: { default: null },
      runeTemplate: { default: '' },  // SFC 源码（运行时动态注入）
    };
  },

  parseHTML() {
    return [{ tag: 'div[data-rune-name]' }];
  },

  renderHTML({ HTMLAttributes }) {
    return ['div', mergeAttributes(HTMLAttributes, {
      class: 'rune-node',
      'data-rune-name': HTMLAttributes.runeName,
    })];
  },

  addNodeView() {
    return VueNodeViewRenderer(TiptapRuneView);
  },
});
```

  name: 'TiptapRuneView',
  components: { NodeViewWrapper },

    });

    return { runeComponent, RuneComponent };
  },
});

```javascript
// src/components/ui/editor/rune-engines/tiptap-engine/index.js
import { Editor } from '@tiptap/vue-2';
import { RuneNode } from './TiptapRuneExtension';

class TiptapRuneEngine {
  name = 'tiptap';
  description = 'ProseMirror + Vue 2 Node View + Schema 驱动';
  techStack = 'ProseMirror + Vue 2 + NodeView';

  editor = null;

  mount(container, options) {
    this.editor = new Editor({
      element: container,
      extensions: [
        StarterKit,
        RuneNode,
        // 其他基础扩展...
      ],
      content: { type: 'doc', content: [{ type: 'paragraph' }] },
      editable: !options.readOnly,
    });
  }

  loadRuneCards(cards) {
    // 通知所有符文节点实例刷新模板
    // 通过遍历 editor state 的所有 rune 节点，更新 runeTemplate 属性
    this.cards = cards;
  }

  insertRune(rune, value) {
    const nodeId = `rune-${Date.now()}`;
    this.editor.chain()
      .insertContent({
        type: 'rune',
        attrs: { runeId: rune.id, runeName: rune.name, runeNodeId: nodeId, runeValue: value, runeTemplate: rune.template }
      })
      .run();
    return { runeId: rune.id, nodeId, value };
  }

  // ...
}
```

**教学要点**：
- ProseMirror 的 Schema 先验约束（atom 节点）
- Transaction-driven 修改（`editor.chain().insertContent().run()`）
- NodeView 作为 ProseMirror DOM 渲染的"接管层"
- Vue NodeView 中 `nodeViewProps` 暴露 `node`、`update`、`deleteNode` 等能力

### 3.3 Editor.js 符文引擎（`editorjs-engine`）

**技术基础**：Editor.js 2.x，每个 Tool 独立管理 DOM 生命周期

**架构特点**：
- Block Tool 是一个类，通过 `render()` 返回 HTMLElement，通过 `save()` 提取数据
- 无虚拟 DOM，每次变更手动更新 DOM（通过 Tool 实例引用）
- 数据输出为纯 JSON（Block 的 `data` 字段）
- 支持 Block Tune（块级操作菜单）

**集成方式**：

```javascript
// src/components/ui/editor/rune-engines/editorjs-engine/RuneBlockTool.js
class RuneBlockTool {
  static get toolbox() {
    return { title: '符文', icon: '⚡' };
  }

  constructor({ data, config, api, readOnly }) {
    this.api = api;
    this.readOnly = readOnly;
    this._data = data || {};
    this.wrapper = null;
    this.runeComponent = null;  // Editor.js 无框架集成，这里用原生 DOM
  }

  render() {
    this.wrapper = document.createElement('div');
    this.wrapper.classList.add('cdx-rune-block');

    const card = document.createElement('div');
    card.classList.add('rune-card');
    card.style.borderColor = this._data.color || '#8b5cf6';

    const header = document.createElement('div');
    header.className = 'rune-header';
    header.innerHTML = `
      <span class="rune-icon">${this._data.icon || '✨'}</span>
      <span class="rune-name">${this._data.name || '符文'}</span>
    `;

    const body = document.createElement('div');
    body.className = 'rune-body';
    body.textContent = this._data.value || this._data.desc || '';

    card.appendChild(header);
    card.appendChild(body);
    this.wrapper.appendChild(card);

    // 如果有 SFC 模板，尝试动态渲染
    if (this._data.template && !this.readOnly) {
      this._mountTemplate(card, this._data);
    }

    return this.wrapper;
  }

  save(blockEl) {
    return {
      runeId: this._data.runeId,
      name: this._data.name,
      icon: this._data.icon,
      color: this._data.color,
      value: this._data.value,
      template: this._data.template,
      desc: this._data.desc,
    };
  }

  validate(savedData) {
    return !savedData || typeof savedData.runeId !== 'string';
  }

  _mountTemplate(container, runeData) {
    // Editor.js 不内置框架集成
    // 可选：通过 hel-micro/wujie 微前端框架挂载 SFC
    // 或降级为静态渲染
  }
}

RuneBlockTool.outputData = 'tool';  // 输出为 { tool: { ... }, data: { ... } }

// 注册为全局 Tool
window.RuneBlockTool = RuneBlockTool;
```

```javascript
// src/components/ui/editor/rune-engines/editorjs-engine/index.js
import EditorJS from '@editorjs/editorjs';

class EditorjsRuneEngine {
  name = 'editorjs';
  description = 'Block Tool 独立 DOM 管理 + 纯 JSON 输出';
  techStack = 'Block Tool + Vanilla JS + JSON';

  editor = null;
  runeCards = [];

  async mount(container, options) {
    this.editor = new EditorJS({
      holder: container,
      readOnly: options.readOnly ?? false,
      tools: {
        rune: window.RuneBlockTool,
        // 内置工具
        paragraph: { class: Paragraph, inlineToolbar: true },
        header: Header,
        list: List,
      },
      data: { blocks: [] },
    });
  }

  loadRuneCards(cards) {
    this.runeCards = cards;
    // Editor.js 工具注册是初始化时完成的
    // 符文卡片作为工具配置传递
  }

  async insertRune(rune, value) {
    const nodeId = `rune-${Date.now()}`;
    await this.editor.blocks.insert('rune', {
      runeId: rune.id,
      name: rune.name,
      icon: rune.icon,
      color: rune.color,
      value: value ?? rune.desc,
      template: rune.template,
      desc: rune.desc,
    });
    return { runeId: rune.id, nodeId, value };
  }

  async getContent() {
    const saved = await this.editor.save();
    return JSON.stringify(saved, null, 2);
  }

  async setContent(jsonString) {
    const data = JSON.parse(jsonString);
    await this.editor.render(data);
  }
}
```

**教学要点**：
- Block Tool 的独立生命周期（`render()` / `save()` / `validate()`）
- 每个 Block Tool 实例持有自己的 DOM 引用（`this.wrapper`）
- 纯 JSON 输出（`{ blocks: [...] }`）而非 HTML
- 工具注册是初始化阶段静态的（不支持热更新工具列表）

### 3.4 Milkdown 符文引擎（`milkdown-engine`）

**技术基础**：Milkdown 7.x（ProseMirror + Vue 3 组件系统）

**架构特点**：
- 基于 `@milkdown/kit`，插件化架构，`$node()` 定义节点，`$view()` 注册 Vue 3 NodeView
- 上下文切片（Ctx/Slice）驱动，依赖注入风格
- 每个内置节点（如 Code Block、Image）都是 `$node + $view` 配对的插件
- Vue 3 headless 组件挂载到 ProseMirror NodeView 容器

**集成方式**：

```typescript
// src/components/ui/editor/rune-engines/milkdown-engine/RuneNode.ts
import { $node, $view } from '@milkdown/utils';
import { toggleMark, wrapIn } from '@milkdown/kit/commands/mark';
import { editorViewOptionsCtx } from '@milkdown/kit';
import { Node, mergeAttributes } from '@milkdown/kit/拓展/core';
import type { Ctx } from '@milkdown/kit/ctx';

// 1. 定义符文节点（Schema 层）
export const RuneNode = $node('rune').with(
  // 配置节点行为
).schema((ctx) => ({
  group: 'block',
  atom: true,
  defining: true,
  attrs: {
    runeId: { default: null },
    runeName: { default: '' },
    runeNodeId: { default: '' },
    runeValue: { default: null },
    runeTemplate: { default: '' },
  },
  parseDOM: [{
    tag: 'div[data-rune-name]',
    getAttrs: (dom) => ({
      runeId: dom.getAttribute('data-rune-id'),
      runeName: dom.getAttribute('data-rune-name'),
      runeNodeId: dom.getAttribute('data-rune-node-id'),
      runeValue: dom.getAttribute('data-rune-value'),
    }),
  }],
  toDOM: (node) => ['div', mergeAttributes({
    class: 'milkdown-rune-node',
    'data-rune-name': node.attrs.runeName,
    'data-rune-id': node.attrs.runeId,
    'data-rune-node-id': node.attrs.runeNodeId,
  })],
}));

// 2. 定义符文视图（Vue 3 渲染层）
export const RuneView = $view(RuneNode).with((ctx) => {
  return () => {
    const container = document.createElement('div');
    container.className = 'milkdown-rune-view';

    // Milkdown 官方 Vue 3 集成
    // 使用 @milkdown/plugin-component 或自定义 Vue 3 app mount
    const { mount, unmount } = createVue3App({
      container,
      props: {},
    });

    return {
      dom: container,
      update: (updatedNode, decorations) => {
        // ProseMirror 文档更新时调用
        if (updatedNode.type.name !== 'rune') return;
        // 更新 Vue 组件 props
      },
      destroy: () => {
        unmount();
      },
    };
  };
});
```

```javascript
// src/components/ui/editor/rune-engines/milkdown-engine/index.js
import { Editor, editorStateOptionsConfig } from '@milkdown/kit';
import { RuneNode, RuneView } from './RuneNode';

class MilkdownRuneEngine {
  name = 'milkdown';
  description = 'ProseMirror + Vue 3 $node/$view 插件 + Ctx 依赖注入';
  techStack = 'ProseMirror + Vue 3 + Milkdown Plugin';

  editor = null;

  async mount(container, options) {
    this.editor = await Editor.make()
      .config(editorStateOptionsConfig({
        defaultValue: '# 符文编辑器\n\n请从左侧选择符文...\n',
      }))
      .use(RuneNode)
      .use(RuneView)
      .use(...)
      .create();
  }

  loadRuneCards(cards) {
    // Milkdown 的节点在 Schema 注册后不可动态添加
    // 但可以通过 transactions 更新现有符文节点的 attrs
    this.cards = cards;
  }

  insertRune(rune, value) {
    const nodeId = `rune-${Date.now()}`;
    const { state, dispatch } = this.editor.view;
    const runeNode = state.schema.nodes.rune.create({
      runeId: rune.id,
      runeName: rune.name,
      runeNodeId: nodeId,
      runeValue: value,
      runeTemplate: rune.template,
    });
    const tr = state.tr.insert(state.selection.to, runeNode);
    dispatch(tr);
    return { runeId: rune.id, nodeId, value };
  }
}
```

**教学要点**：
- `$node()` / `$view()` 配对的插件设计哲学
- Ctx（上下文）切片系统 — 依赖注入而非全局状态
- Milkdown 自身即是"ProseMirror + 插件"的二次封装
- `SchemaReady` Timer 控制初始化顺序

## 七、关键风险与取舍

### 7.1 Vue 2 / Vue 3 Runtime 冲突

**问题**：Memocast 使用 Vue 2，Milkdown 使用 Vue 3，Tiptap 官方推荐 Vue 3（但 `@tiptap/vue-2-renderer` 存在）。同时引入两个 Vue runtime 可能导致全局状态混乱。

**方案**：
- Tiptap：使用 `@tiptap/vue-2-renderer`，与 Memocast Vue 2 共用 runtime（风险低）
- Milkdown：使用 shadow DOM 或独立 `<div id="milkdown-root">` 隔离 Vue 3 runtime，或降级为 Vanilla JS NodeView（风险中）
- Editor.js：纯 Vanilla JS，无需 Vue，SFC 降级为静态渲染或通过 hel-micro 隔离（风险中）

### 7.2 SFC 动态编译在非 Vue 环境

**问题**：Muya 和 Tiptap 的 SFC 编译依赖 `vue-template-compiler`，Editor.js 和 Milkdown（Vanilla）没有 SFC 运行时。

**方案**：
- 复用 Memocast 现有 SFC 编译逻辑（`normalizeRuneSfc` + `compileTemplateToFunctions`）
- 在非 Vue 引擎中，通过 `new Function('h', 'return ' + compiled.render)` 手动调用 render 函数
- 或降级：非 Vue 引擎直接渲染 SFC 的静态表达（HTML 模板插值 + 简单状态）

### 7.3 数据层共用性

符文定义数据（`RuneCard`）存储在 SQLite（通过 IPC），四种引擎共用同一份数据源，无需新建数据库表。

### 7.4 对现有功能的影响

- `Muya.vue` 不修改（除非抽取 SFC 编译函数）
- `Monaco.vue` 不修改
- `SettingsDialog.vue` 只新增一个入口，不改现有 UI
- `RuneFormDialog.vue` 不修改

## 十、四种引擎横向对比（供设计文档/教学使用）

| 维度 | Muya | Tiptap | Editor.js | Milkdown |
|------|------|--------|-----------|----------|
| **底层框架** | snabbdom | ProseMirror | 自研 DOM Manager | ProseMirror |
| **虚拟 DOM** | 是（snabbdom）| 否（直接 DOM）| 否（直接 DOM）| 否（直接 DOM）|
| **Vue 集成方式** | 原生 Vue.$mount | VueNodeViewRenderer | 不可用（Vanilla）| $view + Vue 3 headless |
| **自定义节点** | Block 树 + functionType | `Node.create() + addNodeView()` | Block Tool 类 | `$node + $view` 插件 |
| **数据模型** | Markdown Text ↔ Block Tree | ProseMirror JSON | 纯 JSON `{ blocks }` | Markdown AST |
| **Schema 约束** | 无（Markdown 解析）| 有（ProseMirror Schema）| 无 | 有（Milkdown Schema）|
| **动态加载** | 支持（VNode diff）| 支持（NodeView recreate）| 不可（工具静态注册）| 支持（Plugin injection）|
| **SFC 渲染** | 完整（Vue 2 runtime）| 完整（Vue 2 runtime）| 降级（静态）| 完整（Vue 3 runtime）|
| **代码规模** | ~200KB | ~100KB | ~50KB | ~150KB |
| **上手难度** | 中（专有架构）| 低（文档完善）| 低（API 简单）| 中（概念多）|
| **教学价值** | Block 树 IR 设计 | Transaction 驱动 | Tool 生命周期 | 插件依赖注入 |
