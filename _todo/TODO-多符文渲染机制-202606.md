## 1. 计划依据与背景

### 1.1 TODO 文档 TODO-多符文渲染机制-202606.md 现状

文档原计划引入 Muya / Tiptap / Editor.js / Milkdown 四种引擎做"符文渲染教学样本"。本次校验结论：**整个方向应放弃**。原因如下，且其中多条是联网验证后才能 100% 确认的硬约束。

### 1.2 联网 + 代码校验后的事实

| 编号 | 文档说法 | 实际情况 | 影响 |
|---|---|---|---|
| F1 | Muya / Tiptap / Editor.js / Milkdown 四引擎并列 | 仓库 `src/components/ui/editor/echo/` 下已存在完整 `EchoRegistry.js` / `EchoRuntime.js` / `builtinEchoes.js`（11 个内置回响 + 9 个 rune handler + safeEvalFactory 动态编译 anno_source + `afterRender()` 副作用派发），它本身就是"引擎无关"渲染层 | 多引擎方向与现有架构重复 |
| F2 | `@tiptap/vue-2-renderer` 包名 | 官方包名是 `@tiptap/vue-2`（v3.23.6，2026/5/21 发布），`@tiptap/vue-2-renderer` 拼写错误 | 文档需改写依赖名 |
| F3 | Milkdown 与 Vue 2 兼容 | **`@milkdown/vue` v7.20.0（2026/3/30）`vue: ^3.0.0` peer dep，强制 Vue 3**；v7.9.0 已从 web components 切换到 Vue 3 | Milkdown 在 Vue 2 项目中不可用 |
| F4 | Muya 仍是 snabbdom 版 | **`marktext/muya` 独立仓库 2026/5/29 已 ARCHIVED**；新版本 TS 重写在 MarkText monorepo `@muyajs/core`，与 `muya/lib` 不兼容 | Muya 升级路径不通（短期仍能用现状 snabbdom 版） |
| F5 | BlockNote 替代 | BlockNote 是 **React-first**（依赖 `@tiptap/react`），Vue 2 需经 Veaury 桥接 React | 集成成本远大于收益 |
| F6 | Editor.js SFC 渲染需 wujie/hel-micro 隔离 | 仓库已依赖 `wujie-vue2@1.0.29` 和 `hel-micro@4.15.3`，**该假设成立**；但 Editor.js 2.31.6 数据模型 `{time, blocks, version}` 与 Muya block tree 互转成本高 | 仅 SFC 隔离可行，编辑器级互操作不可行 |
| F7 | Tiptap 3.x ProseMirror 1.x 仍是现代组合 | 验证：Tiptap 3.26.1（2026/6/11），ProseMirror 1.22+ 已修复 XSS 漏洞 | 借鉴 Schema 思路可行 |
| F8 | 文档说"@tiptap/vue-2-renderer 存在" | **官方包名正确形式是 `@tiptap/vue-2`** | 文档需修正 |
| F9 | Tiptap Vue 2 包无 SFC 动态编译能力 | `@tiptap/vue-2` 仅暴露 `VueNodeViewRenderer` + `NodeViewWrapper` + `nodeViewProps`（vue.extend），**不解决"运行时编译 SFC 字符串"**；EchoRuntime 已自管 | 借鉴其生命周期 API 即可，编译器我们自己已有 |
| F10 | BlockNote custom block 需 React | `createReactBlockSpec` 仅产 React spec，**Vue 2 无法直接复用** | 不引入 |

### 1.3 决策

放弃"四种引擎并列"路线，**专注打磨现有 EchoRuntime 体系**。本计划因此重新组织 TODO 文档：删去多引擎部分，替换为"借鉴先进 MD 编辑器设计哲学的可落地优化清单"。

## 2. 现有 EchoRuntime 架构盘点（用作后续优化基线）

参见 `src/components/ui/editor/echo/EchoRuntime.js`：
- 9 个内置 rune handler（growth / shatter / skywalk / twinbloom / mindsteal / lucky / disperse / tbd / clock）
- 11 个内置回响（`BUILTIN_ECHO_CARDS` 在 `builtinEchoes.js`）
- `compileDefinition()` 用 `safeEvalFactory` 动态编译 `anno_source` 字符串
- `renderToHtml()` 输出固定结构 `<span class="ag-echo-inline" data-echo-inline="true" data-rune-id="..." data-rune-kind="...">`
- `afterRender(container, { cleanupFirst })` 派发到对应 handler；handler 返回 cleanup 函数
- `registerRuneHandler(raw, fallbackId)` 与 `unregisterRuneHandler(id)` 提供动态注册/注销
- 副作用约定：scope ∈ {siblings, prev-block, block, document}

参见 `src/components/ui/editor/echo/EchoRegistry.js`：
- `refresh(echoCards)` 重建 echoIdMap / echoMap
- `getById / getByName / has / getAll / isBuiltin / canDelete`
- `render(token)` 与 `renderToHtml(token)` 转发到 runtime

参见 `src/components/ui/editor/editor/echo/builtinEchoes.js`：
- 11 个 anno_source 模板，全部走 `create*AnnoSource()` 工厂
- `BUILTIN_RUNE_IDS` 集中维护 runeId 列表

## 3. 可借鉴的优化点（来自 Tiptap / BlockNote / ProseMirror）

按"借鉴代价/收益"排序，全部限定在不打乱现有 Muya + EchoRuntime + Vue 2 体系的前提下：

### 3.1 引入 Rune Token Schema 校验（借鉴 ProseMirror）

- 目标：避免当前 `parseEchoAttrs` 在 `EchoRuntime.js:85-100` 用简单 splitTopLevel 解析时的边缘 case 漏检（已正确处理引号/嵌套深度，但缺少 key 命名约束、value 类型范围约束）
- 来源：ProseMirror `Schema` 在节点 create 之前给 attrs 加验证函数
- 改动：
  - 新增 `src/components/ui/editor/echo/RuneSchema.js`，提供 `validateRuneAttrs(runeMeta)` 与 `validateRuneHandler(handler)` 两个纯函数
  - `EchoRuntime.compileDefinition()` 编译完 `anno_source` 后调用一次 schema 校验；不通过则打 console.warn 并降级为 `createFallbackRenderResult`
  - Muya 侧 token 解析（`src/libs/muya/lib/parser/render/renderInlines/`）保留现状（Muya parser 已有结构校验）
- 风险：低。新增独立文件，不改现有 export 接口。

### 3.2 规范化 Cleanup 协议（借鉴 Tiptap `NodeView.destroy`）

- 目标：当前 `EchoRuntime.afterRender` 已要求 handler 返回 cleanup 函数，但 `twinbloom` 这类 handler 偶尔因 `data-twinbloom-of` 提前命中而返回 undefined，存在脏状态风险
- 来源：Tiptap `NodeView.destroy` 保证多次调用幂等
- 改动：
  - `EchoRuntime` 维护 `this._installed` 数组（已有）扩展为 `_installed: Map<DOMNode, { runeId, cleanup, idempotent: boolean }>`
  - 新增 helper `safeCleanup(installed)` 捕获异常并保证幂等
  - 所有内置 handler 在 `builtinEchoes.js` 的对应 `handler()` 实现里增加幂等保护（用 `WeakSet` 记录已处理节点）
- 风险：低。仅 `EchoRuntime.js` 改动约 50 行，9 个内置 handler 各加 2-3 行。

### 3.3 强化 transient effect 隔离（借鉴 BlockNote `transient` decorations）

- 目标：当前 `afterRender` 在 `cleanupFirst=false` 时会**累加** 副作用（如 `disperse` 给容器加 `data-disperse-density`），编辑器连续修改后会出现多个累积属性
- 来源：ProseMirror `Decoration` 每次重渲染都重新计算，不累积
- 改动：
  - `EchoRuntime.afterRender()` 默认行为改为：先在 `cleanupFirst` 上对所有已注册节点执行 cleanup，再重新派发
  - 配合 3.2 的幂等保护，可保证重渲染不累积
  - 新增 `EchoRuntime.options.accumulate = false`（默认 false）作为可调旋钮
- 风险：低-中。影响所有 rune 行为，需要回归测试 9 个内置 handler。

### 3.4 anno_source 编辑器：补 LSP 风格的 hint 与静态校验（借鉴 Monaco）

- 目标：`src/components/ui/dialog/EchoFormDialog.vue` 内的 Monaco anno_source 编辑器目前只展示"如何消费 attrs/prompt"的只读示例，没有基于 echo 实际 schema 的 hint
- 来源：Monaco Language Server Protocol
- 改动：
  - 新增 `src/components/ui/editor/echo/annoHints.js`，根据 echo 的 `id / name / desc / icon / color` 字段以及内置 handler 列表（`RUNE_HANDLERS` 导出的 `id`）生成 Monaco completion provider
  - 在 `EchoFormDialog.vue` 的 Monaco 实例上挂载 provider（按现有 `language="javascript"` 即可）
  - 同时在 `EchoRuntime.compileDefinition()` 失败时，把错误信息通过 store action 写回 settings dialog 的"上次错误"提示
- 风险：中。需要改 dialog，且 Monaco 0.38.0 已锁定。completion provider 本身是标准 API。

### 3.5 节点级 Schema 与 handler 解耦（借鉴 Tiptap `addAttributes` 拆分）

- 目标：当前 `builtinEchoes.js` 中每个 anno_source 模板都把 `runeId / kind / scope / ...` 硬编码在 `attrs` 里，重复样板
- 来源：Tiptap `addAttributes()` 让 schema 与行为分离
- 改动：
  - 在 `EchoRuntime.js` 旁新增 `src/components/ui/editor/echo/runeAttributes.js`，导出 `getDefaultRuneAttributes(runeId)` 把 9 个 rune 的默认 attrs 集中
  - `builtinEchoes.js` 中 9 个 rune 工厂改为 `{ ...getDefaultRuneAttributes('growth'), ...overrides }`
  - `extractRuneMeta()` 顺带读这些 default attrs 做更宽容的 fallback
- 风险：低。纯重构，约减 50-80 行重复。

### 3.6 Content API 加 `getMarkdown()` / `setMarkdown()`（借鉴所有现代编辑器通用模式）

- 目标：`EchoRegistry` 目前只有 `render` / `renderToHtml`，缺编辑器侧通用 content API
- 来源：所有先进编辑器的共同模式（Tiptap `editor.getJSON()` / BlockNote `editor.document`）
- 改动：
  - 不动 `EchoRegistry`（它本来只管渲染）
  - 在 `src/components/ui/editor/Muya.vue` 的 muya 实例旁加一组轻量 helper `src/components/ui/editor/echo/markdownAdapter.js`，提供：
    - `extractRunePositions(markdown)` —— 返回所有 `@xxx{...}(...)` 出现位置 + 解析后的 token
    - `replaceRune(markdown, nodeId, newPayload)` —— 按 nodeId 替换整段回响文本
  - 当前 `Muya.vue:53-99` 的 `RUNE_PLACEHOLDER_FULL_TAG_RE` + `rewriteRunePlaceholderByNodeId` 已经是 echo 的雏形，可统一抽到 adapter
- 风险：中。需要回归 `Muya.vue` 的 `onChange` 行为。

### 3.7 不引入的项（明确"不行"）

- **Milkdown**：Vue 3 强约束，F3
- **BlockNote**：React-first 桥接成本 > 收益，F5
- **Editor.js 引擎并列**：数据模型差异大，F6
- **Muya 升级到 @muyajs/core**：API 不兼容，F4
- **Tiptap 整编辑器并列**：Vue 2 包只是 NodeView 桥，编辑器仍需从头搭，重复造轮子
- **wujie-vue2 跨 runtime SFC 挂载**：仓库已依赖但没必要 — EchoRuntime 已经用 `new Function()` 自管 SFC 编译，与 `Muya.vue` 现状一致；引入 wujie 反而引入新的 runtime 风险
