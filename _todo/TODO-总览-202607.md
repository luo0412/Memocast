## 3. 架构与技术栈决策（对应 `TODO-是否升级技术栈-202607.md`）

**决策**：`保持 Vue 2.7 + Quasar 1 + Element-UI + Ant-Design-Vue 1.x + wujie-vue2`。不升级 Vue3。

**核心论证（与 §2 事实保持一致）**：

- 真正的瓶颈在 Muya 内核 + DOM querySelectorAll + rune handler 派发，**与 Vue 版本无关**。
- Vue2.7 响应式已用 Proxy 重写，Vue2 vs Vue3 < 5% 性能差异。
- 真正风险在 transitive 依赖（`lodash / jquery / ssh2 / node-schedule`），用 `yarn audit` 解。
- 项目护城河是 rune / echo / 本地优先 / wujie 微前端，与 Vue 版本无关。

**不升级期间执行项（M1~M5）** —— 详见 `TODO-是否升级技术栈-202607.md` §2。仅状态口径调整为：

| 阶段 | 状态 | 与现状核对结果 |
|------|------|--------------|
| M1 安全基线（`yarn audit` 升级 transitive） | ⏳ 未启动 | 与现状一致 |
| M2 写法层 XSS 防护（`EchoRuntime.js:171-187` escape） | ⏳ 未启动 | `EchoRuntime.js` 真实位置已变；命名空间从 `171-187` 需重新定位 |
| M3 rune/echo 性能优化（LRU 缓存） | ⏳ 未启动 | 与现状一致 |
| M4 单库替换评估（element-ui → element-plus 独立栈等） | ⏳ 持续 | 与现状一致 |
| M5 长期观察 | ⏳ 持续 | 与现状一致 |

**触发升 Vue3 的条件**（任一条为真再启动，且必须渐进迁移）：

1. Monaco / wujie / Muya fork 等核心依赖停更，**且必须用 Vue3 版本**。
2. 招不到 Vue2 工程师，且人力成本压过迁移成本。
3. 把 coolma 从桌面搬到 Web 端，Vue2.7 + webpack4 成为真瓶颈。
