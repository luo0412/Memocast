# 云函数调研存档（uniCloud + vk-router 路线）

> 2026-07 沉淀。归档自 `_todo/` 多份调研 TODO 的合并结论，用于替代为知笔记作为 Memocast 默认同步/账号形态。

## 1. 调研动机

- WizNote 当前在主项目 `src/utils/api.js` 内以两个对象 `AccountServerApi` / `KnowledgeBaseApi` 直接拼 URL，baseUrl 由模块级变量 `let` + getter/setter 控制，与 store、IPC、数据库层强耦合。
- 一旦为知笔记收紧第三方客户端、调整 token 流程，迁移成本极高；希望以"云函数 provider"抽象兜底，后续 WizNote 仅是一个具体实现。
- 用户希望云函数地址**可在设置框内配置**，不写死进源代码；后续还要支持登录、文件上传。

## 2. 候选方案对比

| 方案 | 客户端 SDK | 调用形态 | 学习成本 | 数据落点 | 备注 |
| --- | --- | --- | --- | --- | --- |
| **uniCloud + vk-router** | `vk.callFunction({url, data, isRequest:true})` 或手写 fetch + `uni-id-token` | 单 router 云函数路由模式（1 个云函数 = N 个 API） | 中 | 阿里云 / 腾讯云 / 软件版 | 国内合规、可托管静态网站 |
| **lafyun (laf)** | `laf-client-sdk` 的 `Cloud` 对象 | `cloud.invoke(name, data)` | 低 | 自带 MongoDB / redis | 全开源、自带 web IDE |
| **自建 Express + JWT** | axios | 普通 REST | 低 | 自建 DB | 没有 serverless 红利 |

**选定**：unicloud + vk-router（url 化形态）。理由：

1. 单 router 云函数路由模式与现有"按模块拆分 API"的思路吻合；
2. url 化后前端可完全脱离 unicloud 客户端 SDK 用 axios 调用，等于"普通 REST"，后续随时能切换到 lafyun 或自建；
3. DCloud 生态与本项目 Electron + Vue2 技术栈相对独立，不会强加 framework。

## 3. 选定方案：uniCloud+vk-router url 化

### 3.1 客户端调用形态

vk-router 在云端开启 url 化后，云端 URL 形如：

```
https://<appid>.bspapp.com/http/router/<service>/<module>/<action>
```

前端 `vk.callFunction` 等价于：

```js
axios({
  method: 'POST',
  url: 'https://<appid>.bspapp.com/http/router/user/kh/login',
  headers: {
    'content-type': 'application/json;charset=utf8',
    'uni-id-token': token,            // 登录后由云函数返回
    'vk-appid': '__UNI__XXXXXX',
    'vk-platform': 'h5'               // 或 'electron' / 'app-plus'
  },
  data: { username, password }
})
```

### 3.2 单 router 云函数路由模式

- 一个名为 `router` 的云函数作为总入口；
- 其内部按 `url` 分发到 `service/<module>/<action>`；
- 公共代码放公共模块，避免 N 个云函数重复样板；
- 客户端侧不需要 import 多个云函数对象，所有调用都走 `cloud.invoke(name, data)`。

### 3.3 前端所需依赖

调研结论：**不引入** 第三方云函数客户端 SDK。

- 理由 1：vk 客户端 SDK 依赖 `vk.appid` / `vk.platform` 在编译期注入，与 Electron + Vue2 链路耦合；
- 理由 2：本项目已用 axios，统一通过 axios 走更便于拦截与错误处理；
- 落地：`src/utils/cloud-router.js`（手写 ~110 行）+ `src/services/cloud/CloudFunctionProvider.js`（统一封装）。

### 3.4 baseUrl 与 token 在前端落点

| 项 | 存储 key | 备注 |
| --- | --- | --- |
| baseUrl | `localStorage.cloudfn.config.baseUrl` | 渲染进程可写，跨窗口同步 |
| appId | `localStorage.cloudfn.config.appId` | vk-appid |
| platform | `localStorage.cloudfn.config.platform` | h5 / electron / app-plus / mp-weixin |
| token | `localStorage.cloudfn.token` | 登录后写；登出清空 |

**不**落 `electron-store`：避免走主进程 IPC、降低 v1 接入面，后续若需要加密可再加。

## 4. 当前（WizNote）需要替换的部分

### 4.1 `src/utils/api.js` 暴露面

| 当前 | 替换为 |
| --- | --- |
| `AccountServerApi.Login` | `cloud.invoke('user/login', { userId, password })` |
| `AccountServerApi.getUserInfo` | `cloud.invoke('user/info', { token })` |
| `KnowledgeBaseApi.getCategories` | `cloud.invoke('note/categories', { kbGuid })` |

### 4.2 `src/store/server/actions.js` 登录态

- `login()` 改为：先 `cloud.invoke('user/login', ...)` 拿 token，存进 `cloud.setToken(...)`，再触发迁移逻辑。
- `logout()` 改为：`cloud.clearToken()` + 触发迁移/清理。

### 4.3 设置框位置

- 新 tab：`cloudFn`（紧邻 `server`），由独立子组件 `src/components/ui/dialog/CloudFnConfigDialog.vue` 实现。
- 父组件 `SettingsDialog.vue` 仅做引入 + 1 个 q-tab + 1 个 q-tab-panel。

## 6. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| unicloud 云端绑死阿里/腾讯 | 调用层只暴露 `cloud.invoke(name, data)`，切换 lafyun 仅需替换 `cloud-router.js` 内部 |
| token 暴露给前端 | 与 WizNote 现状一致；后续可引入 `uni-id-token` 短期 token + refresh |
| 资源上传仍依赖 WizNote | v1 接受双后端并存（控制面 = 云函数，附件 = WizNote）；v2 再用云存储/对象存储替换 |
| HBuilderX 强依赖 | 本次只取 url 化形态，不引入 unicloud-clientDB / clientUI，云端用任意 HTTP 客户端即可调试 |

## 9. 决策点（保留切换/回退通道）

- 若云端部署失败/超预算，可在 `cloud-router.js` 一行把 axios base 换成 lafyun `https://<appid>.lafyun.com`，调用形态不变；
- 若 lafyun 也不满足，可替换为自建 Express，对外仍是 `cloud.invoke(name, data)`，业务代码 0 改动；
- 若用户坚持把资源也搬走，新建 `router/resource/upload` 云函数即可，与 WizNote `KnowledgeBaseApi.upload` 解耦。
